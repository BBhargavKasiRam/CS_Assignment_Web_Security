📋 Attack Flow

  1. Victim is logged in to the app (has a valid connect.sid session cookie).
  2. Victim visits this "attacker" page (e.g., via a phishing link).
  3. The hidden form auto-submits a POST to /update-email.
  4. The browser automatically attaches the victim's session cookie.
  5. Server sees a valid session → updates the email to attacker@evil.com. PWNED

❓ Why It Works

The /update-email route checks only the session cookie. It has no CSRF token verification. Since the browser sends cookies with any request to the origin — even from a different site — the server cannot distinguish a legitimate request from a forged one.
